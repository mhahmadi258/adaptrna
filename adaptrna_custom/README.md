# adaptrna_custom

Tools built for this project rather than shipped with it: task packages under `tasks/`
and external-tool wrappers under `tools/`.

Everything here is **generated by the ToolSmith agent, reviewed by you, and then yours**.
It is deliberately git-tracked — this is source code you can diff, commit, and hand-edit,
not runtime state. Nothing regenerates it behind your back: re-running codegen for an
existing name stages a diff for approval rather than overwriting.

```
tasks/<task_name>/          a new engine task: three files, no engine changes
    task.py                 @register_task subclass of BaseDownstreamModule
    datamodule.py           LightningDataModule producing (tokens, target) batches
    config.yaml             task YAML, layered on engine/configs/base.yaml
tools/<family>.py           external-tool wrapper: SPEC + typed functions
```

Task packages are discovered automatically — the training entrypoint and the ToolHub
runtime import every `tasks/*/task.py` so `@register_task` has fired before a task is
trained or served. A module that fails to import is reported by name; it does not break
the others.
